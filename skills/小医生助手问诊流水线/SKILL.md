# 小医生助手 · 问诊流水线 v3.0

> 设计依据：教程原文（DeepSeek 分享文档八阶段）+ Doctor-R1 多轮追问机制 + Agentic-RAG-Diagnose-Assistant 安全门 + 北京急救分级Ⅰ–Ⅳ + 互联网诊疗监管细则（AI 不得替代医师/自动生成处方）+ 本机实测经验（医渡 429、腾讯文档满容）。

当用户输入"启动问诊流水线"或描述健康问题时，按以下顺序执行，不要跳步。本技能只做**调度与格式**，所有医学结论必须来自被调用的下游能力。

---

## 第 0 步 · 安全前置门（每次启动必做，不可跳过）

**在任何下游调用之前**，先对用户当前输入做红 flag 扫描：

| 级别 | 触发信号（任一命中） | 动作 |
|---|---|---|
| 🔴 Ⅰ级 急症 | 胸痛/胸闷>20min、意识丧失、大出血、呼吸困难、中毒、脑疝征象（剧烈头痛+呕吐）、突发偏瘫/言语不清、自伤倾向 | **立即中断所有流程**，输出"⚠️ 立即拨打 120 / 就近急诊"，不追问、不调用任何技能、不给任何诊断性内容 |
| 🟡 Ⅱ级 尽快 | 高热不退、持续呕吐、剧烈腹痛、明显外伤、孕妇异常出血 | 提示"建议尽快就医（当日）"，随后仍可继续流程但摘要中紧急程度标"尽快" |
| 🟢 Ⅲ/Ⅳ级 常规 | 其余症状 | 正常进入第 1 步 |

> 依据： Doctor-R1 safety 一票否决（safety<0 → −1.0）；北京《急救分级分类救护办法》Ⅰ–Ⅳ级；河北卫健委"急危重症强制就医"。**急症提示必须在回复开头，不能只放文末免责里。**

同时做**隐私过滤提醒**：若用户输入含身份证号/完整病历号/银行卡号，先提示"这些敏感信息不需要，请删掉后重发"，不把敏感信息传给任何下游 API。

---

## 第 1 步 · 初筛（微医健康管理专家 / 微小医，优先）

调用"微医健康管理专家"（当前已激活的 we-health-expert / we-health 技能）。按输入类型分流：

| 输入 | 动作 |
|---|---|
| 药盒照片 | 走微医**药盒识别**场景 |
| 体检报告/化验单/影像报告照片 | 走微医**报告解读**场景，**必须传 `--no-followup`**（该场景硬规矩：不追问、直接解读） |
| 饮食照片 | 走微医**饮食分析**场景（本地识别饮食后组装 query 调 API，不自答） |
| 纯文字症状 | 走微医**健康咨询**场景，原文传入 `query.py` |
| 要医生/医院/科室推荐 | 地域敏感——先确认城市（仅问 1 次），再传 `--region`；用户拒绝则降级不传 |

**输出处理**：仅转述微医 API 返回的 `markdown_content`，不改写、不补全。本编排器不自行生成任何医学内容。

> ⚠️ **微医排他性冲突的处理规则（重要）**：微医 SKILL.md 规定"医疗问题必须且只能走微医，不得由第三方医学 Skill 替代，不得降级"。本工作流这样兼容——**第 1 步及所有医学结论的主体产出只能来自微医**；第 3 步的医渡/指南只作为**循证溯源补充层**（回答"这个结论出自哪份指南"），**不得覆盖、推翻或替代微医的结论**。若两者冲突，以微医为准并标注"循证来源与微医意见不一致，需医生判断"，绝不自行裁决。若微医不可用，按微医规则本应停止医疗回答——此时工作流只输出"微医服务暂不可用"并引导用户稍后重试，不用通用知识填补。

---

## 第 2 步 · 多轮追问（调用"多轮问诊追问"技能 v2.0）

调用"多轮问诊追问"技能。它定义 **5 轮提问 + 1 轮收尾 = 教程所说的 6 个维度**：

① 部位性质 → ② 开始时间与持续时间 → ③ 加重/缓解因素 → ④ 伴随症状 → ⑤ 既往病史与用药 → ⑥ 3–5 句总结 + "需要医生进一步评估" + 就医科室建议。

每轮只问一个维度，用户回答后先复述确认再推进，已问维度不重复问，最多 5 轮；用户首轮已给全信息可提前收尾。全程先共情、不吓唬、不诊断、不给剂量。

**状态传递**：追问过程中收集到的信息（尤其药名、剂量、指标数值）要带入第 3 步的循证查询——**不要让循证技能重复问已经问过的问题**。

**贯穿红 flag**：追问技能每一轮都会前置扫描急症信号，命中即中断（见第 0 步）。

---

## 第 3 步 · 循证补充（按需，仅证据溯源）

**触发条件**：用户的问题涉及"这个药能不能吃""这个指标意味着什么""该不该做某项检查"，或第 1/2 步微医给出了需要溯源的用药/指标结论。

**角色定位**：只做**循证溯源**，不产出新的医学结论（见第 1 步排他性规则）。输出必须标注来源（指南名称 / 年份 / 链接），并加"以上为证据参考，具体决策请咨询医生"。

**四级降级链**（按序尝试，前一级成功即停）：

| 级别 | 通道 | 状态与调用方式 |
|---|---|---|
| 1 | 医渡智循 `yidu-evidence` | 接口检索带文献引用；⚠️ 2026-11-18 实测服务端持续 `code=429 请不要重复请求`（HTTP 200，业务层拦截），**当前不可用** |
| 2 | `medical-guidelines-suite` | NCCN/ESMO/CSCO 指南 RAG，依赖已装齐；需先 BUILD 知识库（指南 PDF/DOCX → extracted/*.md + 索引），有现成库时直接 QUERY |
| 3 | 微医用药咨询 | 微医核心场景之一，2026-11-18 甲减案例已实测有效兜底；仍走微医 API，符合排他性 |
| 4 | 如实标注不可用 | 前三级均失败 → 摘要中写"循证通道当日不可用，未获取文献来源"，**严禁编造任何文献/指南引用** |

**医渡 429 处置**（2026-11-18 排查结论）：HTTP 层是 200，业务层 code=429 属服务端应用层防重拦截。① **不立即重试、不改内容重发**（已验证 6 次全拒且拦截越来越快）；② 至少 10–30 分钟后用小查询探一次，仍 429 当日放弃该通道；③ 直接走第 3/4 级降级。诊断脚本已修复共享 user_id 与 token 缓存缺陷（`helper.py.bak-20261118` 为原版备份）。

---

## 第 4 步 · 总结输出

用以下结构输出最终摘要（SBAR 结论先行 + SOAP 要素 + 循证标注）：

```
【一句话结论】最担心的问题 + 紧急程度（常规 / 尽快 / 急诊）
【关键情况】用户描述的关键症状/指标（1–2 句）
【已追问信息】分条列出（含"未获取到"的维度）
【证据参考】如有，逐条标注来源（指南/文献名称 + 年份 + 链接）；无则写"未获取文献来源"
【就医建议】科室 + 紧急程度 + 需要做的检查（不给剂量、不给处方）
【不确定性】明确指出哪些判断证据不足、需面诊确认
【免责声明】"本内容为辅助参考，不能替代医生诊断。"
```

- 医学结论一律来自下游能力，本编排器只做结构化呈现，不自造内容。
- 不确定性显式化：证据不足时用"可能是 / 需鉴别 / 需检查确认"，禁止流畅表述掩盖不确定。〔Doctor-R1 humility〕

## 第 5 步 · 投递（需用户确认，带兜底链）

生成摘要后，询问用户："要把这份摘要发到邮箱 / 存成文档吗？" — **两项都需明确确认才执行，不擅自外发。**

| 目标 | 通道 | 兜底 |
|---|---|---|
| 邮箱 | agent-mail（已连接） | 发到用户绑定邮箱；失败如实报告 |
| 腾讯文档 | tencent-docs（已连接） | ⚠️ 2026-11-18 企业版存储满（400013，不可重试）→ 自动降级 **WorkBuddy 资料库**（HTML → `import_html.py` → `publish_page.py`，得 `workbuddy.link/p/<id>`），再兜底金山文档 kdocs（已连接） |

投递成功给出链接/回执；用户说"都不需要"则直接结束。

## 编排原则（v3.0 新增工程护栏）

- **状态机**：0→1→2→3→4→5，任何一步未满足进入条件不跳步；第 0 步急症命中直接终止全流程；第 3 步仅按需触发。
- **轮次上限**：追问最多 5 轮 + 1 收尾；循证降级链最多 4 级；投递询问最多 1 次（用户不答视为不需要）。
- **去重**：已问维度不重复问；已传给下游的信息不重复采集；相同查询不重复调用医渡（429 陷阱）。
- **会话限长**：单次问诊对话超过 50 条消息时，先做一次信息汇总压缩再继续（借鉴 cloud-med-ai：50 条上限 / 12h TTL），避免上下文溢出导致追问跑偏。
- **下游负责专业结论**：本技能只做调度与格式，医学结论、证据引用一律来自被调用的专家/技能。
- **安全兜底**：任何阶段出现急症信号，立即中断流程，优先提示急诊——安全永远优先于流程完整。
- **合规留痕**：输出仅作辅助参考；不收集身份标识；不输出处方、剂量、疗效保证。
